# 시간 복잡도

## N이 무엇인지 먼저 정한다

N은 **입력의 크기**다. 반환값이나 결과 숫자의 크기가 아니다.

- 문자열 문제 → 문자열의 길이
- 리스트 문제 → 리스트의 길이
- 입력이 여러 개면 각각 다른 문자로 (N, M)

```
예: 반환값이 2,000,000,000 이하여도
    입력 문자열이 50자면 N은 50이다.
    큰 수를 만드는 데 그만큼 반복하는 게 아니다.
```

<br>

## 제약 조건으로 알고리즘 역산하기

기준은 **1초당 약 10⁸회 연산**이다.
문제의 N 범위를 보고 어떤 복잡도까지 허용되는지 판단한다.

| N의 범위 | 허용 시간 복잡도 | 대표 접근 |
| --- | --- | --- |
| N ≤ 20 | O(2<sup>N</sup>), O(N!) | 완전 탐색, 비트마스킹 |
| N ≤ 10<sup>2</sup> (100) | O(N<sup>3</sup>) | 플로이드-워셜 |
| N ≤ 10<sup>3</sup> (1,000) | O(N<sup>2</sup>) | 이중 반복문, DP |
| N ≤ 10<sup>5</sup> (100,000) | O(N log N) | 정렬, 이분 탐색, 힙 |
| N ≤ 10<sup>7</sup> (10,000,000) | O(N) | 선형 순회, 투 포인터 |

문제마다 시간 제한이 있고 (보통 1~5초), 그 안에 답을 내야 통과한다.
컴퓨터가 1초에 처리하는 연산이 대략 10<sup>8</sup>회 이므로, 비교하여 통과 여부를 미리 판단한다.
파이썬은 C보다 느려서 10<sup>7</sup> 정도로 여유를 두는 편이 안전하다.

**코드를 짜기 전에 방향을 정하기 위해 쓴다.**
N이 100,000인데 이중 반복문으로 접근하면 어차피 안 된다.
다 짜고 제출해서 시간 초과를 본 뒤 갈아엎는 것보다,
제한 조건을 먼저 보고 "정렬로 풀어야겠다"고 정하는 편이 빠르다.
시험은 시간이 제한되어 있어 안 될 방법을 미리 걸러내는 것이 중요하다.

## 자료형별 연산 비용

**같은 로직이라도 자료형 선택으로 복잡도가 달라진다.**

| 연산        | 리스트               | 집합 · 딕셔너리         |
| ----------- | -------------------- | ----------------------- |
| `x in a`    | O(N) — 처음부터 훑음 | O(1) — 해시로 바로 찾음 |
| 추가        | `append` O(1)        | `add` O(1)              |
| 삭제        | `remove` O(N)        | `discard` O(1)          |
| 인덱스 접근 | `a[i]` O(1)          | 불가                    |

리스트의 `in`을 반복문 안에서 쓰면 전체가 O(N²)가 된다.

```python
# O(N²) — new_arr이 커질수록 검사가 느려짐
for x in arr:
    if x not in new_arr:
        new_arr.append(x)

# O(N) — 검사는 집합에, 순서는 리스트에
for x in arr:
    if x not in seen:
        seen.add(x)
        new_arr.append(x)
```

<br>

## 자주 쓰는 연산의 복잡도

```
len(a)                    O(1)
sum(a)  max(a)  min(a)    O(N)
sorted(a)  a.sort()       O(N log N)
"".join(리스트)            O(N)
a.count(x)  a.index(x)    O(N)
```

**문자열 이어붙이기 주의**

문자열은 불변이라 `+`를 쓸 때마다 새 문자열을 만든다.
반복문 안에서 쓰면 O(N²)가 된다.

```python
# 느림 — 매번 새 문자열 생성
result = ""
for c in s:
    result += c

# 빠름 — 리스트에 모았다가 한 번에 합침
result = []
for c in s:
    result.append(c)
result = "".join(result)
```

## 직접 계산해 보기

표만 보지 말고 **제한사항의 최댓값을 복잡도에 넣어 연산 수를 계산**한다.
계산한 값이 10<sup>7</sup> 안쪽이면 안전, 10<sup>8</sup>에 가까우면 위험하다고 본다.
(프로그래머스는 시간 제한을 공개하지 않으므로 여유 있게 잡는다.)

**입력이 여러 개면 각각 따로 넣는다.**
반복 횟수 × 반복 한 번의 비용 = 전체 연산 수.

```
예: 달리기 경주 — players N ≤ 50,000, callings M ≤ 1,000,000

for calling in callings:           # M번
    players.index(calling)          # 한 번에 최대 N번 비교

→ O(M × N) = 1,000,000 × 50,000 = 5 × 10¹⁰  → 시간 초과
→ O(M + N) ≈ 10⁶                            → 통과
→ O(M log N) ≈ 10⁶ × 16 ≈ 1.6 × 10⁷         → 대체로 통과
```

반복 횟수(M)는 줄일 수 없는 경우가 많다.
이때는 **반복 안의 연산 비용**을 줄일 수 있는지 본다.

**log N의 감**

log₂N은 "2를 몇 번 곱해야 N이 되는가"다.

```
log 1,000      ≈ 10
log 100,000    ≈ 17
log 1,000,000  ≈ 20
```

O(N log N)은 사실상 O(N)에 20 정도 곱한 것이라 N이 100만이어도 통과한다.

## 판단 순서

1. 문제의 제한 조건에서 N의 최댓값을 확인한다.
2. 위 표에서 허용 복잡도를 정한다.
3. 짠 코드의 반복 구조를 센다. (중첩 반복문 = 곱하기)
4. 반복문 안에서 O(N)짜리 연산(`in`, `remove`, `index`)을 쓰고 있지 않은지 본다.
